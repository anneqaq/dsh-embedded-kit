# USB 2.0 带宽预算

**本技能自带可执行脚本**，不要手算——事务开销是位级的，手算必漏项。

```bash
node {{PLUGIN_ROOT}}/skills/_shared/run-tool.mjs usb_bandwidth action=bandwidth speed=high transfer_type=interrupt max_packet_bytes=1024 interval_microframes=1
```

入参用 `key=value`；`fit` 动作要传端点数组，属复杂参数，写 `.json` 文件再传路径。
返回含 `checks` / `warnings` / `notes`。

## 三个动作

| action | 算什么 |
|---|---|
| `bandwidth` | 单端点：每帧字节数、总线占用占比、单次事务开销拆解、剩余带宽能装几个事务 |
| `fit` | 一组端点能否装进一个 (微)帧：周期上限、控制保留、批量剩余 |
| `hb` | 高速高带宽端点（`wMaxPacketSize` bit 12..11）描述符自洽性 |

## 硬约束（判定线）

| 项 | FS | HS |
|---|---|---|
| 中断 + 同步合计上限 | **90%** | **80%** |
| 控制保留 | **10%** | **20%** |
| 批量保留 | 不保留任何带宽 | 不保留任何带宽 |

规范依据：USB 2.0 §5.11.3 Bus Time Rationing。

## 包间延迟：没有内置实测值

规范只给区间（总线切换 ≥ 8 位时间、主机连发 ≥ 88 位时间，上限均 192），**实际值随主控、Hub、线缆变化**。

- 不传 `gap_turnaround_bits` + `gap_host_to_host_bits` 就退回规范下限，并在 `notes` 里点名"这是设计上限，量产前必须用分析仪实测替换"
- **LS/FS 的"主机连发 8 位时间"是反推校准值，不是规范原文**：取 8 时位级模型恰好复现规范第 5 章"FS 批量 19 个事务/帧"，取 88 则只有 17。规范没有给 LS/FS 的对应数字

## 服务间隔别把寄存器值当间隔用

- **HS**：`bInterval` 是 `2^(bInterval−1)` 个**微帧**（bInterval 1..16，规范 §9.6.6）
- **LS/FS**：`bInterval` 就是**帧数**（1..255）

## 其他必须记住的

- 所有吞吐数字都是**理论设计上限**（假定事务发满、不 NAK、不重传）。真实吞吐必须在目标主机上实测 —— 主控调度实现、Hub 层级、总线竞争都会显著拉低它
- **不做 SSPLIT/CSPLIT 建模**：LS 设备经高速 Hub 的场景会**高估**可用带宽，必须按 Hub 手册另行核算
- **高带宽只用在 HS 的中断/同步上**（规范 §9.6.6）；单微帧上限 3 × 1024 = 3072 字节；`bit 12..11 = 11` 是保留编码，传了直接报错
- **低速不支持批量与同步**，传了直接报错
- 控制传输用 `data_bytes` 描述数据阶段（无数据阶段的请求如 GET_STATUS 传 0）

## 输出怎么读

`checks` 每项形如 `{ name, pass, detail }`。`bandwidth` 动作会把单次事务的开销逐项拆开（令牌 / 数据 / 握手 / 包间延迟各占多少位）—— **看哪一项占比最大，就知道该往哪里优化**。
