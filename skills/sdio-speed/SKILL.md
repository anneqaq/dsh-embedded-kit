# SD / SDIO / eMMC 速率与吞吐

**本技能自带可执行脚本**，不要手算——开销项多且每项都影响结论。

```bash
node {{PLUGIN_ROOT}}/skills/_shared/run-tool.mjs sdio_speed action=throughput mode=sdr104 clock_hz=200000000 bus_width=4 block_bytes=512
```

入参用 `key=value`；返回含 `checks` / `warnings` / `notes`。

## 四个动作

| action | 算什么 |
|---|---|
| `throughput` | 有效吞吐与效率归因：扣掉命令/响应、块内开销、忙等待、块间空隙、主机开销 |
| `modes` | 列出 16 个速率档的时钟上限 / 允许位宽 / 单双沿 / 信令电压 / 规范速率与出处，并逐档核对算术自洽 |
| `init` | 识别阶段 `f_OD ≤ 400 kHz` 限速校验（`phase=transfer` 则反向判是否忘了提速） |
| `si` | 在**你给的**偏斜上限与负载电容上限之内比较，超限时按同家族退一档 |

## 不内置任何默认值 —— 不传就是乐观上界

**命令/响应往返延迟、写方向 DAT0 忙等待、块间空隙、主机每事务开销**，这四项一个都不内置：

- 不传就按 **0** 计入，并在 `notes` 里明确标注结果是**乐观上界**（真实值只会更低）
- 写方向尤其重要：卡内部写 NAND 的时长随内容 / 磨损 / 温度变化，**必须实测**
- 小块高频事务时**主机开销主导效率**；总线越快，它的相对占比越大

**`max_skew_ps`（组内偏斜上限）与 `max_load_pf`（负载电容上限）必须查你的 SoC / 存储器手册** —— 不给就**不判定**（返回 0 条 checks）。本实现不臆造阈值。

## 为什么"位宽翻 4 倍"不等于"吞吐翻 4 倍"

每块固定带 **18 个时钟**的起始位 + CRC16 + 结束位开销，而且**每根 DAT 线各一份、与位宽无关**。
位宽越宽，这部分固定开销的相对占比越高，所以有效吞吐的增益小于位宽的倍数。

> 注：这个 18 是由规范的数据包令牌 / 包结构推出的，**规范正文未逐字写出"18"**。

## 识别阶段与档位约束

- 识别阶段 **`f_OD ≤ 400 kHz`**（规范硬性）。忘了提速会让吞吐低一到两个数量级，所以 `init` 动作在 `phase=transfer` 时反向判这件事
- 位宽超出该档规范允许范围会被判不通过（例如 **HS400 只支持 8 位**）
- 常见资料把 SDIO Low Speed 写成 200 KB/s，与 `400 kHz × 1 位 = 50 KB/s` 的算术对不上。本实现一律取"**时钟 × 位宽 ÷ 8**"口径，并对这个矛盾单独加告警

## 输出怎么用，不能怎么用

- 全部是**设计值**：不含控制器分频取整、FIFO 停顿、卡内部读写延迟与重传
- **真机吞吐必须用逻辑分析仪 / 总线分析仪实测对齐**
- 效率归因会把各项开销的占比列出来 —— 看哪一项最大，就知道该优化什么

## 输出怎么读

`checks` 每项形如 `{ name, pass, detail }`；`warnings` 里会点名"哪些开销按 0 计入，结果是乐观上界"。
