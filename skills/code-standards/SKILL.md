# 嵌入式 C 代码规范

## 用法

这份规范是**可直接固定为项目基准**的：把它落到仓库的 `CODING_STYLE.md` 并在审查时逐条对照。
每条都写成**可判定**的形式 —— 对错能一眼看出，不出现"尽量""建议保持良好风格"这类无法执行的条款。

落地三步：
1. 把本文档复制进项目根目录，按项目实际删改（保留你认同的，删掉不适用的）。
2. 在 CI 或提交钩子里跑一遍基础检查（格式、禁止项可用文本搜索兜住）。
3. 审查时**引用条目编号**（如"违反 R12"），让讨论聚焦在规则而非个人偏好。

> 规范的价值不在于"好看"，而在于**让异常写法变成显眼的异常**。
> 一条规则如果无法判定对错，就不是规范，是愿望。

## R1 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 类型 | 小写 + `_t` 后缀 | `state_t`、`uart_cfg_t` |
| 函数 | 小写 + 下划线，模块前缀 | `uart_send_blocking()` |
| 宏 / 常量 | 全大写 + 下划线 | `UART_RX_RING_SIZE` |
| 枚举值 | 全大写 + 模块前缀 | `ST_CONNECTING` |
| 全局变量 | `g_` 前缀 | `g_tick_ms` |
| 静态文件级变量 | `s_` 前缀 | `s_state` |
| 局部变量 | 小写，不用单字母（循环计数 `i` `j` 除外） | `byte_count` |
| 布尔 | `is_` / `has_` / `can_` 前缀 | `is_ready` |

- **R1.1** 禁止用拼音命名；禁止 `a1` `tmp` `data1` 这类无语义名。
- **R1.2** 单位写进名字：`timeout_ms`（不是 `timeout`）、`period_us`、`size_bytes`。
  单位混用（把 µs 当 ms 传）是嵌入式头号低级事故。

## R2 类型

- **R2.1** 凡是表达二进制数据、寄存器值、协议字段、长度的一律用**固定宽度类型**：
  `uint8_t` / `int16_t` / `uint32_t`… 禁止裸 `int` / `long` / `char`（其宽度随平台变）。
  例外：返回值语义为"数量/状态"的局部计数可以，但入参与接口一律固定宽度。
- **R2.2** 中断与主循环共享的变量**必须** `volatile`。**注意 `volatile` 只保证可见性，不保证原子性** ——
  多字节量与读改写仍需临界区保护。
- **R2.3** 布尔用 `stdbool.h` 的 `bool` / `true` / `false`，不要用 `int` 当布尔（`if (x == 1)` 掩盖了 x 可能是 2）。
- **R2.4** 有符号与无符号禁止混用比较。`if (len - 1u < 0u)` 恒为假 —— 这类 bug 编译器告警能抓到，必须清零告警。
- **R2.5** 结构体直接按字节收发或写 Flash 时，必须显式处理填充与字节序：
  用 `__packed` / `__attribute__((packed))`（按工具链），且字段逐个做字节序转换。

## R3 寄存器访问

- **R3.1** 禁止在业务代码里出现裸地址与魔法数。所有寄存器通过厂商头文件定义的符号访问，
  位掩码定义成有名字的宏。
- **R3.2** **读-改-写寄存器时保留保留位（reserved / 未定义位）的原有值**。
  直接 `REG = 0x03` 会清掉不该动的位；正确做法是掩码操作 `REG = (REG & ~MASK) | (val << SHIFT)`。
- **R3.3** 明确哪些寄存器是**写 1 清标志（W1C）**的。对 W1C 寄存器用读改写会误清其他标志 ——
  必须直接写目标位。
- **R3.4** 位域（bit-field）**禁止**用于寄存器映射与协议字段：分配顺序（低位先/高位先）因编译器与架构而异。
  一律用移位与掩码。
- **R3.5** 位操作宏参数加括号，且**有副作用的自增/函数调用不能传给位宏**：

  ```c
  #define BIT(n)              (1UL << (n))
  #define REG_SET_BITS(r, m)  ((r) |= (m))
  /* 反例：REG_SET_BITS(x, BIT(i++)) 会因宏展开把 i 自增两次或零次 */
  ```

## R4 函数

- **R4.1** 单一职责。一个函数只做一件事；超过约 50 行或嵌套超过 4 层就拆分。
- **R4.2** **入参必须校验**：指针非空、长度非零、范围合法。校验失败返回错误码，不静默继续。
- **R4.3** **禁止无界循环**。任何等待硬件标志的循环都必须带上限或超时：

  ```c
  /* 反例：硬件一坏，永久卡死 */
  while (!SPI_TXE()); 

  /* 正例 */
  for (uint32_t guard = 0; guard < SPI_TIMEOUT_LOOPS; guard++) {
      if (SPI_TXE()) { SPI_WRITE(data); return ERR_NONE; }
  }
  return ERR_TIMEOUT;   /* 超时必须能被上层看到 */
  ```
- **R4.4** 函数返回错误码时，**调用方必须检查**。允许显式忽略，但要用 `(void)` 明确标注"有意忽略"。
- **R4.5** 不在函数内做动态分配（若项目允许堆），尤其禁止在中断与实时路径里分配。
- **R4.6** 禁止在头文件里定义变量（会多重定义）。头文件只放声明、类型、宏与 `static inline` 函数。

## R5 错误处理

- **R5.1** 统一错误码类型（如 `err_t` 枚举），禁止混用 `-1` / `0` / `false` / 全局错误变量。
- **R5.2** 每个可能失败的操作都要有**明确规定的失败行为**：返回错误、进入安全态、或重试并限制次数。
  "假设不会失败"是最贵的假设。
- **R5.3** 错误路径要有计数或状态上报（至少一个错误计数器），否则现场偶发故障无法定位。
- **R5.4** 断言（`assert`）只用于**不可恢复的程序逻辑错误**，不用于输入校验（输入校验要返回错误码）。
  发布版本要么禁用断言，要么让断言进入安全态而不是死循环。

## R6 中断

- **R6.1** 中断函数名必须与启动文件向量表中的符号**完全一致**（换工具链时这一步最容易漏）。
  建议统一加后缀便于搜索：`UART1_IRQHandler` 之类按厂商约定。
- **R6.2** ISR 内只做最小必要工作：清标志、取数据、写环形缓冲、置标志位，然后退出。
- **R6.3** ISR 内**禁止**：忙等、长延时、`malloc`/`free`、`printf`、带锁接口、任何可能阻塞的总线事务。
- **R6.4** 跨 ISR 共享的环形缓冲采用**单生产者/单消费者**结构（各指针只有一个写者），免锁；
  否则必须用临界区（关中断）保护。
- **R6.5** 缓冲区满时**丢弃并计数**，绝不在 ISR 内等待。丢帧计数器是排查现场问题的关键证据。
- **R6.6** 若用 RTOS，ISR 内必须用 `FromISR` 变体，且中断优先级数值必须 ≥ `configMAX_SYSCALL_INTERRUPT_PRIORITY`。

## R7 文件组织

- **R7.1** 每个 `.c` 配一个同名 `.h`；头文件**自包含**（单独 include 它能编译通过）。
- **R7.2** 头文件用 include guard（`#ifndef` 或 `#pragma once`，项目内统一一种）。
- **R7.3** 只暴露必要的接口：模块内部函数与变量用 `static` 收敛在 `.c` 内。
- **R7.4** include 顺序统一：本项目头文件 → 厂商/第三方 → 标准库。
- **R7.5** 禁止跨模块直接访问别的模块的全局变量，必须通过接口函数。

## R8 明确的禁止项（出现即为缺陷）

- **R8.1** 软件延时循环：`for (i = 0; i < N; i++);` —— 会被优化掉、随主频变化、阻塞一切。用硬件定时器。
- **R8.2** 绝对时间比较：`if (now > deadline)` —— 计时器回绕后会永久失效。
  用无符号减法：`if ((uint32_t)(now - since) >= limit)`。
- **R8.3** 无超时的标志等待循环（见 R4.3）。
- **R8.4** 把悬空引脚当输入使用。悬空输入的休眠电流不可预测。
- **R8.5** 中断里修改状态机的状态变量（应由 ISR 投递事件，主循环消费）。
- **R8.6** 未使用引脚的默认状态未处理（建议配为模拟模式或带确定电平的输入）。
- **R8.7** 靠链接顺序或未定义行为"能跑就行"的写法。
- **R8.8** 注释掉的大段代码。用版本控制，不要用注释保存历史。

## R9 注释

- **R9.1** 注释解释**为什么**，不解释**做什么**（代码本身说明做什么）。
- **R9.2** 每个硬件相关的魔法数必须注明来源：寄存器字段名、数据手册章节或计算公式。
- **R9.3** 每个对时序有要求的代码段必须写明**具体约束与条件**，例如
  "本次传输须在 50µs 内完成，否则从站会 NAK"；不要写"要快"。
- **R9.4** **引用数据手册章节号前必须确认该章节存在**；记不准就写"需查该手册中 XXX 相关章节"。
  绝不允许为了语气笃定而编造章节号或页码。
- **R9.5** TODO 必须带责任人或 issue 号，否则会永久遗留。

## R10 格式化

- 项目内统一一种缩进（建议 4 空格或制表符，二者不要混）；行宽 ≤ 100。
- 大括号：函数必换行，控制语句可不换行（项目内统一）。
- **启用编译器告警并清零**：GCC `-Wall -Wextra`，AC6 从 `-Weverything` 起步再按需关闭；
  **禁止用强制转换把告警按掉**。告警清零是这套规范里单项收益最高的一条。
