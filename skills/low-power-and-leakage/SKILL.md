# 低功耗设计与漏电诊断

## 铁律：先量后改，先分类再定位

低功耗问题有两类，**处理方法完全不同**：

- **平均电流偏高** → 运行时间/占空比问题 → 优化软件与工作模式（可算，用 `power_budget`）
- **休眠电流偏高** → 漏电问题 → 与占空比无关，优化运行时间**毫无用处**，必须逐条查通路

**判据**：把占空比压到接近零，电流降不下来多少 → 是漏电，不是功耗预算问题。先分清这个，否则会白干几天。

---

## 一、功耗预算（可提前算清的部分）

用 `power_budget` 把各模式的电流按占空比或时长加权：

- 每个模式的电流取**数据手册典型值或实测值**，注明来源 —— 不要拿"看起来合理"的数。
- **常驻漏电（`sleep_leak_ua`）必须单列**：它不随占空比下降，是电池寿命的**硬地板**。占总电流比例越大，越该先查引脚漏电与稳压器静态电流，而不是继续压运行时间。
- 看**哪个模式贡献最大**：优化从贡献最大的那一项下手，而不是从最低功耗模式下手。
- 电池可用系数别取 1：低温、老化与截止电压通常吃掉 20% 以上容量。

两个必须注意的边界：
- **数据手册的"典型值"常在 25°C、标称电压、无外设时钟条件下测得**。高温下漏电可翻数倍，必须在最坏工况下核对。
- **µA 级测量本身容易错**：万用表 µA 档的内阻会改变电路状态（相当于串了个负载），且量程切换瞬间有冲击。µA 级要用专门的电流表/功耗分析仪，或串一个已知电阻测压差。

## 二、低功耗模式与唤醒源

选模式的判据是**三件事的组合**：域保持哪些（RAM / 寄存器 / RTC）、唤醒时间多长、唤醒源有哪些。

| 模式量级 | 通常保持 | 唤醒时间 | 典型用途 |
|---|---|---|---|
| 运行降频 | 全部 | 即刻 | 计算量可压缩的场景 |
| 浅睡眠（如 Sleep / Idle） | 全部，时钟停 | µs 级 | 等待外设/事件，频繁唤醒 |
| 深睡眠（如 Stop / Deep-sleep） | RAM、部分寄存器 | 数十 µs ~ ms | 秒级~分钟级周期采样 |
| 待机（如 Standby / System OFF） | 仅备份域（RTC + 少量备份寄存器） | ms 级（相当于复位重启） | 分钟级~天级上报 |

要点：
- **唤醒时间要算进功耗**：唤醒一次的"爬升"过程本身耗电，唤醒越频繁越不划算。存在一个**最优上报周期**（唤醒开销 × 频率 与 睡眠电流 × 时间 的平衡点），按实际数据算，不要拍。
- **唤醒后要能恢复上下文**：深睡眠会丢 RAM 之外的东西；待机相当于重启，程序要从复位入口走一遍并**识别出"是唤醒而非冷启动"**（读唤醒标志）。
- **唤醒源要能全部识别**：多个唤醒源时，必须逐一记录并分发，否则会"睡下去立刻醒"（某个未预期的引脚活动在反复唤醒）。
- **关闭外设时钟**：休眠前把用不到的外设时钟关掉。一个没关的 ADC / 比较器 / RC 振荡器的静态电流，常常比 MCU 本身的睡眠电流还大。
- **调试器与看门狗**：连着调试器测低功耗**测不准**（调试逻辑本身耗电）；看门狗若在睡眠期间继续跑，要么它自己是唤醒源，要么必须在睡眠前置位让它保持。

## 三、漏电诊断（重点）

### 3.1 先分类，再动手

毫安级"莫名漏电"通常只出自这几类，按**出现频率**排序：

| 类别 | 典型量级 | 特征 |
|---|---|---|
| **引脚电平冲突 / 常态上下拉** | 几十 µA ~ 几十 mA | 随引脚状态变化；拔掉外部器件立刻改善 |
| **外设未关时钟 / 外设内部保持使能** | 数十 µA ~ 数 mA | 关掉该外设立刻下降 |
| **稳压器/LDO 静态电流 + 反馈分压** | 几 µA ~ 数百 µA | 与 MCU 状态无关，一直在 |
| **上电指示 / 分压网络 / 上拉电阻网络** | 由电阻算得出 | 按 V/R 手算就能对上 |
| **电容漏电 / 劣质电容** | 数 µA ~ | 高温下明显变大 |
| **PCB 表面污染 / 助焊剂残留 / 潮湿** | 不定 | 洗板后改善；湿度相关 |

**手算校验永远先做**：任何一个跨接在电源与地之间的电阻，都贡献 `V/R`。`3.3V/10kΩ = 330µA`。把原理图上所有"一直存在"的电阻加起来，很多"神秘漏电"当场就解释了。

### 3.2 引脚漏电：最容易被忽略的一类

**核心判据只有一条：引脚两端同时被拉向相反方向。** 只要有电流的完整回路，就会持续耗流。

用 `leak_pin` 工具逐脚判定。以下是它覆盖的典型情形：

#### ★ 经典案例：CMOS 推挽输出 + MCU 内部上拉

```
       VDD ──[MCU 内部上拉]──┬── MCU 引脚
                            │
                            └── 外部器件 CMOS 推挽输出（此刻输出低）
                                     │
                                    GND
```

**电流从 VDD 经内部上拉电阻，灌进外部输出的低边管，持续不断。**
`3.3V / 40kΩ ≈ 82.5µA`，24 小时不间断，直接吃掉电池寿命。

为什么难查：
- **软件不报错**：引脚读回来确实是低电平，逻辑完全"正常"。
- **示波器看不出**：没有信号变化，是纯直流。
- **只有电流表看得见**：而且表现为"休眠电流比设计值高几十 µA"。

**修法**：关闭该引脚内部上拉（改浮空输入或模拟输入），电平交给外部驱动决定。
若该引脚**同时**是开漏总线（如 I²C）需要上拉，则上拉应由**总线上的单一位置**提供，
而不是 MCU 内部 —— 且要确认外部器件在该时刻确实处于高阻。

#### 其他必须逐条核对的情形

| 情形 | 是否有漏电 | 说明 |
|---|---|---|
| 内部上拉 + 外部 CMOS 推挽**低** | **有** | 经典案例，`V/Rpu` |
| 内部上拉 + 外部开漏**低** | **有** | 与上同（开漏低时下管导通） |
| 内部上拉 + 外部开漏**高阻** | 无 | 这正是开漏总线的正确用法 |
| 内部下拉 + 外部 CMOS 推挽**高** | **有** | 对称情形 |
| 内部上拉 + 外部下拉电阻 | **有** | 两个电阻分压，`V/(Rpu+Rext)` |
| MCU 推挽输出 + 外部推挽输出**反向** | **有且危险** | 对电源/地短路，可达数十 mA，发热损伤 |
| 输入悬空（无上下拉、外部高阻） | **有** | CMOS 输入级两管部分导通 + 噪声致振，休眠电流不可预测 |
| 模拟输入却使能了数字上下拉 | 有 | 漏电且影响 ADC 读数 |
| 未使用引脚悬空 | 有 | 未使用引脚建议配为**模拟模式**或带确定电平的输入 |

### 3.3 诊断流程（二分法，从外到内）

1. **先测基线**：记录当前休眠电流，写成数字。
2. **拔掉/断开外部器件**：如果电流立刻下降 → 是引脚相关的漏电（回到 3.2 逐脚查）。
   这一步**直接把问题范围砍成两半**，别跳过。
3. **逐个关闭外设时钟**：每个外设关掉后测一次，找出仍在耗电的那个。
4. **把 MCU 所有 IO 置为已知状态**：全部模拟输入（或全部浮空输入并断开外部）。
   电流下降说明有引脚漏电。
5. **回到原理图手算**：把所有跨电源与地的电阻按 `V/R` 加一遍，看能否解释剩余的部分。
6. **只剩最后一点时**：考虑 LDO 静态电流、电容漏电、PCB 清洁度与湿度 —— 这些不在软件可控范围内，需要改硬件或工艺。

**每一步都测并记录**，不要一次改三样。这个流程的价值就在于每步只动一个变量。

### 3.4 休眠前引脚复核清单

进入低功耗模式**之前**，逐脚确认（这也是 `leak_pin` 用来做的事）：

- [ ] 每个引脚的模式是**明确指定**的（不是上电默认值、不是"忘记配置"）
- [ ] 输出引脚：电平是否会导致外部器件持续耗流？能否在休眠前改为**高阻/模拟**？
- [ ] 输入引脚：有没有确定电平？悬空的必须有上下拉或改成模拟
- [ ] 外部器材是 CMOS 推挽输出、且此刻在驱动的：**该引脚的内部上下拉必须关闭**
- [ ] 开漏总线（I²C 等）：上拉由谁提供？休眠期间总线是否被拉低（某些器件的下拉会把总线拉死）？
- [ ] 上电指示 LED / 分压网络 / 外部上拉：是否需要在休眠期间保持？能否用 MOSFET 断开？
- [ ] 未使用引脚：配为模拟 或 带上拉的输入（**不要浮空**）
- [ ] **复位期间与初始化之前**的默认状态同样要确认 —— 上电到初始化完成这段时间的状态，是很多"上电瞬间大电流"的原因

## 四、数据手册里必须去查的几个电气参数

做电量计算时最常被漏掉的，是**手册已经给出、但没人去翻**的那几个数。它们既影响漏电，也影响采样精度。

| 参数 | 手册里的常见名字 | 用在哪 | 取值原则 |
|---|---|---|---|
| 内部上拉/下拉电阻 | R_PU / R_PD / R_PULL | 计算引脚漏电 `V/R` | **手册多给 min/typ/max 范围**。最坏情况取 **min**（电阻最小 → 电流最大）。**只填典型值会低估现场耗流** |
| 引脚输入漏电流 | I_LK / I_IL / I_IH | 每个引脚的常驻漏电 | **未使用的引脚也有**，是休眠电流的**硬地板**。总漏电 ≈ 引脚数 × 最大值，常为几百 nA ~ 几 µA |
| ADC 采样保持电容 | C_ADC / C_S / C_sample | 采样电荷转移电流 | 直接决定动态项，见下节 |
| ADC 内部采样开关电阻 | R_ADC / R_SW | 采样建立时间 | 与外部源阻抗**相加**后决定能否建立 |
| ADC 输入漏电流 | I_LK(ADC) | ADC 常态漏电 | 按通道累加，不采样时也存在 |
| 引脚/焊盘电容 | C_IO / C_PAD | 高频翻转的动态功耗 `C·V²·f` | 只在高速翻转时显著 |
| 复位期间 IO 状态 | 手册的"复位状态"表 / Pinout 表 | 上电到初始化完成这段时间的状态 | **很多"上电瞬间大电流"就出在这里**，不能只看初始化之后 |

**三条纪律**：

1. **范围一律取最不利端**，不要只抄典型值。典型值常在 25 ℃、标称电压下测得；
   高温下漏电可翻数倍、上下拉电阻也会变小。做最坏情况设计要留余量。
2. **温度与电压条件要看清楚**。手册表格的脚注写了测试条件（温度、VDD、使能状态），
   抄数时要连着条件一起抄。
3. **手册没给的量不要猜**。比如输入级的贯穿电流通常不给，只能实测 —— 那就写"需实测"，
   不要拿一个"看起来合理"的数填进电量表。

### 4.1 ADC 采样电流：最常被整项漏掉的开销

**物理过程**：ADC 每次采样，都要把内部采样保持电容充到输入电压。这个电荷从信号源取走，
按采样率重复，折算成平均电流：

```
I_采样 = f_采样 × C_ADC × V_ref × 通道数
```

**特点**（决定了它为什么容易被漏掉）：
- 它**不在**引脚漏电里，也**不在**芯片的工作电流里 —— 是采样网络特有的开销。
- 它**随采样率线性增长**：采样率翻倍，这一项也翻倍。高采样率的场合相当可观。
- 它产生在**采样期间**，所以应计入"正在采样的那个模式"的电流，
  **不是**休眠电流（如果休眠时不采样，这一项就是 0）。
- 上式是**最坏情况**（每次采样都跨越满量程）；输入变化幅度小时实际更小。

**算例**：10 kHz 采样、C_ADC = 8 pF、V_ref = 3.3 V →
`10000 × 8pF × 3.3V = 0.264 µA`。看起来很小，但采样率到 1 MHz 就是 **26.4 µA** ——
足以压过很多 MCU 的整机休眠电流。

### 4.2 源阻抗上限：比功耗更要紧的问题

采样网络是 `(R_源 + R_ADC) × C_ADC` 的一阶 RC。要在采样窗口内建立到 **½ LSB** 以内：

```
t_采样 ≥ (n + 1) · ln2 · C_ADC · (R_源 + R_ADC)

⇒ R_源上限 = t_采样 / ((n+1) · ln2 · C_ADC) − R_ADC
```

**不满足的后果不是耗电，而是读数错**：采样值偏低、且随输入电平非线性 —— 表现为
"小信号准、大信号偏"，非常容易被误判成"ADC 不准"或"参考电压有问题"。

**算例**：12 位、t_采样 = 1500 ns、C_ADC = 8 pF、R_ADC = 1 kΩ →
`R_源上限 = 1500ns / (13 × 0.693 × 8pF) − 1kΩ ≈ 19.8 kΩ`。
若源阻抗是 100 kΩ 的分压网络，**必须**加长采样时间或降低源阻抗（减小分压电阻、加运放缓冲）。

**设计取舍**：
- **分压电阻越大越省电**（常态电流 `V/(R_top+R_bottom)` 小），
  但**源阻抗也会变大**，与建立时间冲突。这是低功耗设计中一对典型的相互制约，
  必须按上面的式子找一个两边都满足的点，而不是各自优化。
- 需要高阻源 + 高采样率时，加一级运放缓冲，或选带 PGA / 缓冲输入的 ADC。

### 4.3 把这几项接到电量计算里

`V/R` 能算出来的一切，都应该**算**而不是拍：

- 分压网络、到地电阻、外部上拉的常态电流 → 全部按 `I = V / R` 加进 `sleep_leak_ua`
- 引脚数 × I_LK → 加进 `sleep_leak_ua`
- ADC 采样电流 → 加进**采样模式**的电流，不是休眠电流
- 引脚漏电通路（上下拉对打）→ 用 `leak_pin` 逐脚判定，取**最坏情况**合计

这样得到的 `sleep_leak_ua` 才是有依据的数字。拿着它去算电池寿命，结论才站得住；
反之拿一个"我估计大概 20 µA"填进去，寿命估算就只是自我安慰。

## 五、常见误判

- **把漏电当成占空比问题**：优化运行时间一周，休眠电流一点没降。先分清类别。
- **迷信数据手册的睡眠电流**：那个数是在"所有外设关、所有 IO 为模拟、无外部电路"条件下测的。真实板子远高于它。
- **用万用表 µA 档测低功耗**：表的内阻会改变电路，读数不可信。用专用电流表或串已知电阻测压差。
- **连着调试器测功耗**：调试器供电会掩盖真实电流。
- **只查 MCU 不查外围**：外部 EEPROM/收发器/传感器的待机电流经常是主因。
- **改了配置没复测**：低功耗必须**每改一项测一次**，否则无法归因。
