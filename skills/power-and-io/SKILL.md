# 功耗、电源树、引脚漏电与 ADC 采样

**本技能自带可执行脚本**，不要手算——这四个都是多步累加，且最容易漏项。

```bash
node {{PLUGIN_ROOT}}/skills/_shared/run-tool.mjs power_budget modes=... battery_mah=1000
node {{PLUGIN_ROOT}}/skills/_shared/run-tool.mjs i2c_bus mode=standard cb_pf=200
```

入参用 `key=value`；**参数里有数组或嵌套对象时必须写 `.json` 文件再传路径**（例如 `power_tree` 的 `rails`、`power_budget` 的 `modes`）：

```bash
node {{PLUGIN_ROOT}}/skills/_shared/run-tool.mjs power_tree args.json
```

## 四个动作

| 工具名 | 算什么 |
|---|---|
| `power_budget` | 各模式按占空比或时长加权成平均电流，可折算电池寿命；指出哪个模式贡献最大 |
| `power_tree` | 逐轨 LDO 耗散 / DCDC 效率 / 结温，超限报警；给出整树输入、耗散、效率与最热的轨 |
| `leak_pin` | 引脚电平冲突与漏电通路判定；给 vdd 与上拉阻值才给电流数值 |
| `adc_load` | 采样电荷转移电流、常态静态负载、源阻抗上限、采样窗口内能否建立到 ½ LSB |

## 功耗预算：待机漏电是"硬地板"

- 平均电流 = Σ(各模式电流 × 占空比)，但**常驻漏电（引脚漏电 + 稳压器静态电流）与电池自放电不随占空比下降** —— 它们是电池寿命的硬地板。优化占空比优化不掉它们，必须单独列出
- `battery_derating` 默认 0.8（温度/老化/截止电压折损）；电流值应取数据手册典型值或实测
- 结果会指出**哪个模式对平均电流贡献最大** —— 优化从那里下手，别凭直觉

## 电源树：两个最容易记错的结论

- **LDO 耗散 = (Vin − Vout) × Iout，效率 = Vout / Vin** —— 效率**与电流无关**，压差全部变成热。所以"用 LDO 降压"在压差大时是纯发热方案
- **DCDC**：`Pin = Pout / η`；**结温** `Tj = Ta + Pd × Rθja`，允许功耗 `(Tj_max − Ta) / Rθja`
- `Rθja` / `Tj_max` / `η` **必须来自器件手册**，本实现不内置默认值

## 引脚漏电：通路由拓扑决定，电流要查手册

- 最典型的现场难定位问题：**MCU 使能内部上拉、而该脚接的通讯器件是 CMOS 推挽输出且此刻输出低** —— 电流从 VDD 经上拉电阻持续灌进外部低边。休眠时吃几十 µA，软件无报错、示波器看不出，只有电流表看得见
- 同时覆盖：下拉对打高电平、推挽对推挽短路、开漏总线上误配下拉、悬空输入贯穿电流、内外上下拉分压
- **电流数值需要 `vdd` 与内部上拉电阻**（**查数据手册**）。**最坏情况取手册的 `min` 电阻**，不是典型值 —— 手册标 40 kΩ typ / 20 kΩ min 时，漏电流按 20 kΩ 算
- 缺 vdd 或上拉阻值时只报通路、不算数字，不会替你猜一个电阻

## ADC 采样：建立不足比功耗问题更致命

- **采样电荷转移电流 = 采样率 × C_sample × Vref × 通道数**。它随采样率线性增长，**不在引脚漏电里、也不在运行电流里** —— 不显式加上就低估电池消耗
- **源阻抗上限**：`R_source` 必须在采样窗口内把 `C_sample` 建立到 ½ LSB。建立不足会让**读数偏低且非线性**，这不是标定能修的，是设计问题
- 常态静态负载单列：分压网络 `V / (Rtop + Rbottom)`、到地电阻、每通道输入漏电流 `I_LK`（**未使用的通道也有**）
- `C_sample` / `R_ADC` / `I_LK` / 采样窗口**必须从数据手册取** —— 本实现不做任何默认推测，缺哪项就报错点名

## 输出怎么读

`checks` 每项形如 `{ name, pass, detail }`；`pending` 列表点名**因缺数据而未算的项**（不是 0，也不是通过）。所有输出都是**设计值**；实际漏电、整机功耗、建立时间必须实测。
