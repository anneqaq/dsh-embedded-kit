# 嵌入式固件代码审查清单

## 第 0 步：先问清三件事，不要假设

审查前必须确定，缺哪一项就问，**不要靠推测填空**：

1. **有没有 RTOS？** 裸机和 RTOS 的适用规则完全不同。FreeRTOS 专属的规则（栈水位 API、
   `FromISR` 变体、优先级反转）在裸机项目里**一条都不适用**，硬套只会产生噪音。
2. **目标 MCU 与资源**：型号、Flash、RAM、主频。同一个写法在 32KB/4KB 的 Cortex-M0 和
   512KB/128KB 的 M4 上结论可能相反。
3. **工具链**：Keil AC5 / AC6 / GCC / IAR。编译器的警告能力和优化行为差别很大。

## 一、ISR 规则（裸机与 RTOS 通用）

- **ISR 只做最小必要工作**：清标志、取数据、置标志位或写环形缓冲，然后退出。
- **ISR 内绝不忙等、绝不长延时**。等一个字节发完、等 ADC 转换完成都是错的设计。
- **ISR 内禁止调用任何可能阻塞的函数**（`malloc`、`printf`、文件/总线事务、带锁的接口）。
- **RTOS 专属**：中断内调用 FreeRTOS API 必须用 `FromISR` 变体，且用
  `xQueueSendFromISR` 而不是 `xQueueSend`；绝不在 ISR 里调 `vTaskDelay`。
- **共享变量必须处理并发**：
  - 主循环读、ISR 写的变量：加 `volatile`，且**读多字节量（uint16/32）时要关中断或用
    单次原子读**，否则可能读到撕裂值。
  - 计数器累加、`a = a + 1` 这类读改写：主线与 ISR 之间必须用临界区（关中断 / 自旋锁）。
- **中断优先级陷阱**：Cortex-M0 没有优先级分组配置；M3/M4 上若在中断里调用 RTOS API，
  优先级数值必须 ≥ `configMAX_SYSCALL_INTERRUPT_PRIORITY`，否则系统状态会被破坏。

## 二、内存与栈

- **禁止在初始化之后使用动态分配**。嵌入式项目优先静态分配或固定内存池；
  一旦用了 `malloc`，就要为堆外碎片和分配失败设计行为。
- **栈大小必须算，不能猜**。裸机做法：启动文件里把栈区预填固定的魔数（如 `0xA5A5A5A5`），
  跑一轮最坏路径后扫描**未被改写的边界**得到实际栈深；再对照 `.map`/`.htm` 文件核对。
  RTOS 做法：`uxTaskGetStackHighWaterMark()`。
- 检查每个栈帧里的**大局部数组**：`char buf[512]` 放在栈上，在 4KB RAM 的 MCU 上就是事故。
- 确认大数组在 Flash 还是 RAM：加 `const` 才会进 Flash；漏了 `const` 会白白吃掉 RAM。

## 三、错误处理与超时（最容易漏的一节）

- **检查每一个可能失败的调用**：写总线/读寄存器/初始化返回码，不能只写 happy path。
- **每一个等待循环都必须有超时**。反例（教科书级错误，但真实代码里到处都是）：

  ```c
  while (!LL_SPI_IsActiveFlag_TXE(spi));   /* 硬件一坏，永久卡死 */
  ```

  正确形状：带上限计数或超时时间，失败时返回错误码或进入安全状态。

- **看门狗要真的能救你**：确认喂狗点只在主循环的正常路径上，而不是放在定时器中断里
  （那样即使主循环死了，狗也照样被喂，看门狗形同虚设）。
- 掉电/复位后要能回到安全状态：输出脚先设安全电平，再初始化外设。

## 四、未定义行为与类型

- **别做违反对齐/别名的类型转换**。把 `uint8_t*` 转成 `uint32_t*` 再解引用，在 Cortex-M0
  上可能触发硬错误；协议解析一律用 `memcpy` 到局部变量再读，或逐字节拼装。
- **结构体直接按字节收发/写 Flash 时**，必须确认填充字节不会乱入：用 `__packed`
  （或逐字段序列化），并明确字节序（ARM 默认小端，但协议常规定大端，要显式转换）。
- **有符号/无符号混用**：`if (len - 1 < 0)` 在 `len` 为无符号时永远为假。
- 位移超过类型宽度、`int` 的左移溢出，都是 UB。
- **启用编译器告警并清零**：GCC 用 `-Wall -Wextra`，AC6 用 `-Weverything` 起步再按需关；
  不要用强制转换把告警按掉。

## 五、数值与实时性

- **不要在中断或实时路径里用浮点**（除非确认有 FPU 且时序够）。定点/整数运算是安全选择。
- **ISR 里不做除法**：整数除法在无硬件除法器的 M0 上要走软件例程，耗时可达数十周期。
- 涉及时序的地方，把**约束写成具体的数字与条件**，例如
  "本次传输须在 50µs 内完成，否则从站会 NAK"；而不是"要快"。

## 六、审查输出规范

1. **指出问题时给行号与具体改法**，不要只说"建议优化"。
2. **精确到硬件量**：说"PA5 作为 SPI1_SCK，8 MHz"，而不是"配置一下 SPI"。
3. **主动标注 UB**：说清"这个转换在 Cortex-M4 上不加 `__packed` 就是 UB，它会静默读错"。
4. **区分"可判定"与"需实测"**：
   - 语法/规则类问题可以直接断言对错；
   - 时序、功耗、栈深这类**必须实测**的结论，只能给设计目标与验证方法，
     **不得把设计值说成实测值**。
5. **引用资料时，不确定的章节号必须标注"待核"**。明确写下"见 XX 手册第 X 节"
   之前，要确认该章节确实存在；记不准就写"需查该芯片参考手册中 DMA 仲裁相关章节"，
   **绝不允许为了语气笃定而编造章节号**。

## 七、常见反模式速查

| 反模式 | 后果 | 修法 |
|---|---|---|
| 无超时的 `while(!flag);` | 硬件故障时永久卡死 | 加上限/超时 + 错误返回 |
| ISR 里 `printf` / `malloc` | 阻塞、重入、栈爆 | 移到主循环；用环形缓冲传递 |
| 跨 ISR 的 `uint32_t` 直接读 | 撕裂值 | 临界区保护或原子读 |
| 大局部数组 | 栈溢出 | 改静态或内存池 |
| 漏 `const` 的查找表 | 白吃 RAM | 加 `const` 进 Flash |
| 只在定时器中断喂狗 | 主循环死了也照样喂 | 移到主循环正常路径 |
| 只处理 happy path | 现场偶发死机难复现 | 全部分支 + 故障注入测试 |

## 八、跨厂商 / 跨架构差异（**不要预设用户用的是哪家芯片**）

前面七节是共性问题。以下是**因厂商与架构而异**的部分 —— 审查时先确认目标平台，
再决定适用哪一列。**绝不要因为看过某个型号的代码，就把它的结论套到别的芯片上。**

### 8.1 中断模型

| 平台 | 要点 |
|---|---|
| ARM Cortex-M3/M4/M7 | NVIC 带优先级分组（`NVIC_SetPriorityGrouping`）；在中断里调用 RTOS API 时，优先级数值必须 ≥ `configMAX_SYSCALL_INTERRUPT_PRIORITY`，否则会破坏内核状态 |
| ARM Cortex-M0/M0+ | **没有优先级分组配置**，可用优先级位更少；给 M3 写的优先级配置代码拿过来可能无效 |
| ARM Cortex-A（AArch64） | GIC 而非 NVIC，中断控制器与异常等级概念完全不同，不能套用 Cortex-M 经验 |
| RISC-V | 中断控制器是实现相关的（PLIC / CLIC / 各家自研），**必须查具体 SoC 手册**；`mstatus.MIE` 与 CSR 操作需配对 |
| Xtensa（ESP32 系） | 中断分级 + 高优先级中断有专门的 C 调用约定要求；部分中断不能调用 FreeRTOS API |
| AVR / 8051 / PIC | 多为单向量或有限向量、常无优先级嵌套；`cli()/sei()` 或对应寄存器开关中断，临界区粒度要更小心 |
| MSP430 | 有可配置优先级但规则与 ARM 不同，`__disable_interrupt()` / `__enable_interrupt()` |

### 8.2 位操作与原子性

- **ARM Cortex-M3/M4/M7**：有位带（bit-band）区，单比特置位天然原子；**M0/M0+ 没有位带**。
- **AVR / 8051 / PIC**：多字节量的读写通常要关中断保护；AVR 的 `sbi/cbi` 是原子的，但读-改-写宏不是。
- **RISC-V**：无位带；原子操作依赖 A 扩展（`amoadd` 等），基础 ISA 里没有。
- 通用结论：**读改写（`x |= mask`）在"主线 + 中断"之间永远需要保护**，无论哪家芯片。

### 8.3 对齐与访问宽度

- **ARM Cortex-M0/M0+**：非对齐访问会**产生 HardFault**（M3/M4 支持部分非对齐访问，但跨设备内存仍可能出错）。
  协议解析一律用 `memcpy` 到局部变量或逐字节拼装，不要对 `uint8_t*` 做 `uint32_t*` 转换。
- **AVR / 8051 / PIC**：字节寻址、寄存器 bank 概念；指针与内存空间（Data / Program）分离。
- **Harvard 架构（AVR / 8051 / PIC）与 von Neumann（ARM / RISC-V）的区别**会导致：
  函数指针与数据指针不可互换；常量默认放在 Flash 还是 RAM 的规则不同
  （AVR 需要 `PROGMEM` + `pgm_read_*`，否则字符串会白占 RAM 且行为不同）。

### 8.4 存储空间与指针语义

- 8 位平台常有多套地址空间（Data / Program / EEPROM），指针需要限定符（如 AVR 的 `__flash`）。
  把 32 位平台上写的通用指针操作搬过去会编译失败或运行错乱。
- 部分平台（8051 / PIC）有 bank / page 切换，跨 bank 调用与查表需要额外的辅助代码，
  体积与耗时都要单独评估。

### 8.5 编译器与扩展关键字

| 工具链 | 打包结构体 | 中断函数 | 内联 |
|---|---|---|---|
| GCC / Clang | `__attribute__((packed))` | `__attribute__((interrupt))` | `__attribute__((always_inline))` |
| Keil AC5 | `__packed` | `__irq` / 中断向量名匹配 | `__inline` |
| Keil AC6 | `__attribute__((packed))` | 向量表名匹配（`startup_*.s`） | 同 GCC |
| IAR | `__packed` | `#pragma vector=` / `__interrupt` | `#pragma inline` |
| XC8 / SDCC | 各家专有 | 专有 | 专有 |

- **位域（bit-field）的分配顺序（低位先/高位先）因编译器与架构而异** —— 涉及协议或寄存器映射时不要依赖位域，显式用移位与掩码。
- 中断函数名必须与启动文件里的向量表符号一致；换工具链时这一步最容易漏。

### 8.6 浮点与运算能力

- **Cortex-M0/M0+ 无 FPU**（部分 M4F/M7 有单/双精度 FPU）；AVR / 8051 / PIC16 无 FPU。
- RISC-V 的 F/D 扩展是**可选**的，同一内核型号的不同配置可能一个有、一个没有 —— 确认 `-march` 是否含 `f`。
- 无 FPU 时浮点是软件模拟：体积与周期都要单独评估，实时路径尽量用定点。
- 无硬件除法器的平台（M0 / AVR 部分型号）整数除法也走软件例程。

### 8.7 审查动作

1. **先问平台**：芯片型号 + 内核 + 工具链 + 有无操作系统。这三项决定上面哪一列适用。
2. **不要把某型号的结论当通则**。看到"这条在 STM32 上没问题"不等于"在 M031 / ESP32 / AVR 上没问题"。
3. 跨厂商迁移代码时，逐条核对 8.1–8.6，尤其是中断向量名、打包属性、非对齐访问、多内存空间指针。
4. 遇到不确定的寄存器、时钟树或中断控制器行为，**明确说"需查该型号参考手册确认"**，
   不要用另一家芯片的相似经验替代。
