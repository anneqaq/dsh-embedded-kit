# 串行通讯协议编写与审查清单

## 第 0 步：先固定协议参数，别边写边猜

动手前必须逐项确认并写进注释或文档，缺一项就是一个未来的现场故障：

| 项目 | 必须明确的内容 |
|---|---|
| 物理层 | 电平（TTL / RS-485 / RS-232）、是否隔离、终端电阻与偏置 |
| 波特率 | 具体数值 + **允许误差**（晶振误差累计后仍要在容限内） |
| 帧格式 | 数据位 / 校验位 / 停止位（如 8E1、8N1） |
| 字节序 | 多字节字段是大端还是小端（Modbus 是大端） |
| 寻址 | 从站地址分配、广播地址（Modbus 为 0） |
| 超时 | 字符间超时、帧间静默、应答超时、重试次数 |
| 错误恢复 | 超时后重发？丢弃？进错误状态？需不需要上报？ |

## 一、帧设计（自定义协议时）

- **必须有帧同步手段**：要么固定帧长，要么带同步头 + 长度字段，要么带结束符。
  只靠"读到足够字节就算一帧"在噪声环境下必然错位。
- **必须带校验**：CRC16 优先（比累加和/奇偶校验强得多）。校验要覆盖**地址与功能码**，
  不能只校验数据域。
- **长度字段要防溢出**：收到长度 N 后要校验 `N <= 缓冲区容量`，否则栈/堆被冲掉。
  这是嵌入式通讯里最经典的远程可利用缺陷。
- **收到坏帧要能重新同步**：丢弃当前帧后，要能从字节流里找回下一个同步头，而不是一直错位。
- **最小帧长检查**：比最短合法帧还短的输入直接丢。

## 二、CRC 实现的三个经典坑

1. **字节序**：Modbus RTU 的 CRC 是 **低字节先发**。写成大端是最高频的错误，
   现象是"从站无任何响应"（因为整帧被静默丢弃）。
2. **多项式方向**：Modbus 用反射多项式 `0xA001`、初值 `0xFFFF`、无最终异或；
   CRC-16/CCITT 用 `0x1021`。**两者不通用**，抄代码前先确认协议要求的是哪一种。
3. **把 CRC 本身也参与计算**：计算时应只覆盖"不含 CRC 的载荷"。

快速自检向量（Modbus RTU）：帧 `01 03 00 00 00 0A` 的 CRC 必须是 `0xCDC5`，
即线上字节为 `01 03 00 00 00 0A C5 CD`。实现完先跑这一组再上板。

## 三、超时与重试

- **每层都要有超时**：字符间、帧间、应答等待、整笔事务。任何一层缺失都会变成永久卡死。
- **Modbus RTU 的静默时间**：
  - 帧间静默 t3.5 = 3.5 个字符时间；字符间超时 t1.5 = 1.5 个字符时间。
  - **波特率 > 19200 时，规范建议改用固定值 t1.5 = 750µs、t3.5 = 1750µs**
    （高波特率下 3.5 个字符时间太短，普通定时器分辨率跟不上）。
  - 字符时间 = (1 起始 + 数据位 + 校验位 + 停止位) / 波特率。
- **重试要有限且带退避**：固定次数（常见 3 次）+ 退避，重试期间不能让上位逻辑无限等待。
- **区分"无响应"和"CRC 错"**：前者可能是地址/接线/使能问题，后者多为干扰、波特率误差、
  或方向切换时序不足。**用不同的计数器分别统计**，否则现场无法定位。

## 四、RS-485 半双工方向切换（最容易出事的一环）

物理事实：半双工只有一对差分线，**发的时候自己也在收**。所以方向切换错了会有两种典型症状：
首字节被截断（DE 使能太晚）或末字节被截断（DE 撤销太早）。

- **DE 使能要提前**：必须在首字节的起始位到达线路之前就置起，提前量 ≥ 收发器的驱动使能时间
  （数据手册里的 tPZH / tPZL）。
- **DE 撤销要延后**：末字节的停止位发完之后，还要再保持 ≥ 驱动关闭时间（tPHZ / tPLZ）
  才能撤销，否则末尾几位会被切断。
- **"发完就切"是错的**：判断依据必须是 **TC（发送完成）标志**，而不是"数据写入发送寄存器"
  或"TC 中断里的第一时刻"。写 DR 只代表数据进了移位寄存器。
- **收发器参数必须查数据手册**，不要凭型号猜。典型需要确认的量：
  驱动使能/关闭时间、传播延迟、共模输入范围、失效保护（fail-safe）行为。
- **总线空闲时的电平**：没有偏置电阻时差分电压接近 0，接收端输出可能振荡，
  表现为"空闲时疯狂收随机字节"。确认是否需要失效保护偏置。
- **共模电压**：两地供电的设备之间若地电位差大，要评估共模范围，必要时加隔离。
  这是"偶发、只在下雨/大功率设备启动时出错"类故障的常见根因。
- **终端电阻**：长线或高波特率下要在两端各接 120Ω；短距离多分支时反而可能不需要，
  照抄别人的板子容易出问题。

## 五、Modbus RTU 专门要点

- 广播（地址 0）**没有应答**，不能等回包。
- 应答异常时功能码最高位置 1：如 `0x83` 是 `0x03` 的异常响应，第三字节是异常码。
  常见异常码：`01` 非法功能、`02` 非法数据地址、`03` 非法数据值、`06` 从站设备忙。
  **异常响应也要走 CRC 校验**，不能因为"功能码不对"就整帧丢弃。
- 常用功能码：`01/02` 读线圈/离散输入、`03/04` 读保持/输入寄存器、
  `05/06` 写单个线圈/寄存器、`0F/10` 写多个线圈/寄存器。
- 寄存器地址常见"协议地址从 1 起、报文地址从 0 起"的偏移差，**审查时必须确认上位用的是哪一套**。

## 六、审查输出规范

1. 审查通讯代码时，**逐项对照第 0 步的参数表**，缺项要明确指出并说明后果。
2. 报告问题时给出**具体场景与症状**，例如"DE 在写 DR 后立即拉低，末字节停止位可能被截断，
   表现为高波特率下偶发 CRC 错"。
3. 时序结论要标注**来源**：由公式算出的叫"设计值"，由示波器/逻辑分析仪抓到的才叫"实测值"。
   **两者不得混用**，更不得把设计值说成实测值。
4. 建议验证方法时给出可操作手段：在 DE 脚与总线 A/B 上同时抓波形、用不同波特率各跑一遍、
   满负载与空载各测一轮。
