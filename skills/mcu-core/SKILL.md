# NVIC、看门狗、调度与栈

**本技能自带可执行脚本**，不要手算——这几项都是"漏一个项就得出相反结论"的类型。

```bash
node {{PLUGIN_ROOT}}/skills/_shared/run-tool.mjs nvic_priority action=preempt implemented_bits=4 sub_priority_bits=0 a_priority=1 b_priority=1
node {{PLUGIN_ROOT}}/skills/_shared/run-tool.mjs watchdog_check action=check timeout_us=100000 worst_feed_interval_us=60000
```

入参用 `key=value`；任务表 / 调用链是数组，写 `.json` 文件再传路径。零参数会让工具报缺参。

## 四个工具

| 工具名 | 算什么 |
|---|---|
| `nvic_priority` | `grouping` 算抢占级数与寄存器位位置；`preempt` 判两个中断能否互相抢占；`latency` 算中断延迟上界 |
| `watchdog_check` | `timeout` / `solve` 算超时与计数参数；`check` 判最坏喂狗间隔是否落在允许区间 |
| `sched_analyze` | CPU 加权占用率、每任务裕量、节拍量化误差、**节拍碰撞扫描**、同拍最坏等待（抖动上界） |
| `stack_depth` | 最坏调用链 + 最深 N 层中断帧 = 静态上界，对比栈区大小与余量；水印反算已用字节 |

## 最容易判错的三处

**① NVIC：抢占位相同则彼此不能抢占。** 子优先级**不产生抢占** —— 两个中断只要抢占位相同，无论子优先级差多少都不能互相打断。这是最常见的误判。
中断延迟上界 = **最长关中断窗口 + 更高优先级 ISR 之和（保守）+ 入栈开销**。`__NVIC_PRIO_BITS` 查手册。

**② 窗口型看门狗：喂太早同样复位。** 判据是**最坏**（最长）喂狗间隔，不是平均；窗口型还要判**最短**间隔。
**不要在中断里喂狗** —— 那会掩盖主循环卡死，是看门狗存在的意义本身被抵消。
另外要检查**上电初始化耗时**是否超过超时（初始化比超时还长就会在启动时被复位）。

**③ 栈的静态上界不等于实测用量。** 函数指针、库函数（printf / 浮点）、中断时机都会额外吃栈。
帧大小取自编译器 `-fstack-usage` 生成的 `.su` 文件，**不要用"变量字节数"**。
必须用**填充法**（魔数填满 + 跑完最坏工况扫水印）或**栈水位寄存器**复核；给了水印地址可反算已用字节。

## 调度：先算再写

`sched_analyze` 有两种模式：

- `cooperative-tick`：一个定时器打节拍、任务轮流执行 —— 会算**节拍能否被任务周期整除**（量化误差）与**最重的一拍能否在一拍内跑完**（节拍碰撞）
- `isr-direct`：各任务挂各自中断

输出里看三样：**CPU 加权占用率**（留多少余量）、**节拍碰撞**（哪一拍超了）、**同拍最坏等待**（抖动上界）。
加功能前先算，别等跑不动再回头。

## 输出怎么读

`checks` 每项形如 `{ name, pass, detail }`。`latency` 与 `sched_analyze` 的输出都是**静态计算值**，真实抖动必须实测（GPIO 翻转 / DWT / 逻辑分析仪）。
